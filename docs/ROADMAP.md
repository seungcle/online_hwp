# 로드맵

## 마일스톤 1 — 완료

HWPX 업로드 → 구조 분석 → 경량 미리보기. 단계별 처리 시간 측정.

## 마일스톤 2 — 완료

자연어 → Edit Plan → 검증 → 바이트 단위 patch → 내려받기.
텍스트 편집만. 이미지는 미리보기에 표시만 하고 원본 바이트를 그대로 보존한다.

## 마일스톤 2의 설계 기록 (참고용)

```text
자연어 요청
  → Cloudflare Worker (OpenAI 프록시)
  → 검증된 Edit Plan (JSON)
  → 브라우저의 결정적 patch engine
  → 새 HWPX 내려받기
```

### 붙이는 순서

1. **patch engine 먼저.** AI 없이, 손으로 만든 Edit Plan으로 결과 HWPX를
   생성하고 한글에서 열리는지 검증한다. 필요한 것은 이미 모델에 다 있다.
   문단마다 텍스트 조각의 바이트 구간(`TextFragment`)을 들고 있으므로,
   바뀌는 구간만 새 바이트로 교체하면 된다. ZIP 재패키징은 엔트리 순서와
   항목별 압축 방식을 원본 그대로 재현해야 한다(`ZipEntry`가 그 정보를 보존한다).
2. **Edit Plan 스키마 확정.** 최소한으로 시작한다.
   ```json
   { "operations": [
     { "type": "replace_text", "paragraphId": "s0-p12",
       "oldText": "2025년 사업 제안서", "newText": "AI 교육 사업 제안서" }
   ]}
   ```
   `oldText`를 반드시 넣고, 적용 전에 현재 문단 텍스트와 일치하는지 확인한다.
   불일치하면 적용하지 않고 사용자에게 알린다. AI가 엉뚱한 문단을 짚었을 때
   조용히 망가지는 것을 막는 안전장치다.
3. **Worker 프록시.** OpenAI 키는 Worker의 secret으로만 둔다. 프론트엔드
   번들에 키가 들어가는 일은 없어야 한다. structured output / tool calling으로
   스키마를 강제하고, Worker에서 한 번 더 검증한 뒤 브라우저로 돌려준다.
4. **보내는 데이터 최소화.** HWPX 파일은 보내지 않는다. 문단 id와 텍스트만
   추린 표현을 보낸다. 개인정보처리방침에 전송 범위를 명시한 뒤에 켠다.
5. **변경 미리보기.** 적용 전에 어느 문단이 어떻게 바뀌는지 보여주고,
   사용자가 승인해야 파일이 만들어지게 한다.

## 지원 범위 넓히기 — 진행 중

실제 양식을 처리하면서 새로운 HWPX 패턴이 나올 때마다 최소한으로 대응하고,
그 양식을 회귀 테스트 fixture로 남긴다.

```text
실제 양식 추가 → 새 패턴 발견 → 최소 기능 추가
  → 해당 양식을 fixture로 저장 → 기존 양식 전체 재검증
```

## 마일스톤 3 — 완료: 알려진 양식 기억

한 번 뜯어본 양식은 다시 뜯어보지 않는다.

```text
처음 보는 HWPX
  → 구조 지문 계산 → D1 miss
  → AI 구조 분석(어느 문단이 무슨 자리인가) → 양식 저장
  → 수정 계획 → 결정적 patch          (AI 호출 2회)

이미 본 양식
  → 구조 지문 계산 → D1 hit → 라벨 대조 통과
  → 저장된 필드 지도를 그대로 사용 (구조 추론 생략)
  → 수정 계획 → 결정적 patch          (AI 호출 1회)
```

실측(dev-sample, 문단 9개): 왕복 5498ms → 1966ms, AI 호출 2회 → 1회.

설계 근거와 개인정보 경계는 [ADR 0002](adr/0002-known-template-store.md)에 있다.
요지만 옮기면:

- 지문은 **뼈대만**으로 만든다. 값이 달라도 같은 양식으로 알아본다.
- 뼈대는 성긴 열쇠라 라벨 대조로 한 번 더 거른다(80% 이상).
- 바이트 오프셋·XML 노드 번호는 영구 식별자로 쓰지 않는다. 논리 경로를 쓴다.
- 어긋나면 자동으로 고치지 않는다. 재분석하고 다음 version으로 남긴다.
- `oldText` 대조와 부분 적용 금지는 그대로다. 양식 기억은 AI 호출을 줄이는
  장치이지 검증을 건너뛰는 장치가 아니다.

### 아직 안 한 것

- 개인정보처리방침에 "양식 구조를 저장한다"를 명시하지 않았다.
- 양식 관리 UI가 없다. `?debug=1` 로 hit/miss만 본다.
- 실제 사내 양식 여러 벌로 지문 안정성을 확인하지 못했다. 합성 fixture와
  dev-sample 까지만 봤다.
